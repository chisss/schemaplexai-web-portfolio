# Semantic Catalog Frontend

This module owns the Phase 1 semantic catalog and ontology workbench.

## Why It Exists

Enterprise data is distributed across heterogeneous databases and uses physical names that business users do not share. This module gives administrators a small, governed workflow for defining business concepts and mapping them to physical data before natural-language analysis is enabled.

## Responsibilities

- List and create tenant-scoped semantic models.
- Create and switch immutable model versions.
- Explore a bounded ontology neighborhood and edit draft node metadata.
- Validate draft versions with SHACL and publish an active version.
- Render loading, empty, read-only, conflict, and unavailable-service states.

Natural-language query execution and SQL generation are outside this module and remain in Phase 2.

## Routes

- `/data-management/semantic-models`: semantic model catalog.
- `/data-management/semantic-models/:modelId`: model version and graph workbench.
- `/data-management/semantic-query`: Phase 2 compatibility entry.

The model catalog uses server-side pagination and supports filtering, model creation, draft creation, and archived-model deletion. The workbench provides version selection, bounded two-hop graph exploration, node editing, SHACL issue navigation, validation, and publishing. On narrow viewports, the node directory and inspector move into drawers.

## API Contract

`src/types/semantic.ts` and `src/api/semantic.ts` define the Phase 1 contract for models, versions, schema snapshots, neighborhood graphs, validation, and publishing.

- Tenant identity comes from the authenticated request interceptor. Components must not send `tenantId`.
- TDB2 graph names are generated by the server. Components must not send `graphIri`.
- Mutable commands carry `expectedRevision` for optimistic concurrency control.
- API status values use lowercase strings at the web boundary.
- Graph reads are bounded neighborhood queries. The browser does not issue SPARQL or edit Turtle.

Natural-language query execution remains outside Phase 1. The compatibility route only directs users to publish a semantic model first.

## Dependencies

- `src/api/semantic.ts` provides TanStack Query hooks and cache invalidation.
- `src/types/semantic.ts` owns the browser-side REST DTOs.
- Ant Design provides form, table, drawer, feedback, and responsive primitives.
- AntV G6 renders the ontology neighborhood; the browser does not execute inference.

## Quick Use

1. Open `/data-management/semantic-models` and create a model for one business domain.
2. Open the model workbench, create or select a draft, then choose a graph node.
3. Edit labels, aliases, data types, and physical mappings in the inspector.
4. Run validation, locate reported nodes, and publish only after the constraints pass.

## Interaction Constraints

- Graph queries default to depth 2 and at most 500 nodes.
- Published and archived versions are read-only in the editor.
- Validation and publishing use the latest known version revision for optimistic concurrency.
- Network and missing-controller failures render retryable error states; production pages do not inject mock data.
